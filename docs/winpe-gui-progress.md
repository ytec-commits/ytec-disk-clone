# WinPEネイティブGUI進捗

更新日: 2026-08-01

## 目的

WinPE起動後にコマンド入力を求めず、Windows側で準備したジョブの確認、
クローンと独立した起動修復、接続ディスク診断を、同じ安全境界から
迷わず操作できる製品画面を提供します。

## 実装済み

- 静的MSVC x64のWin32 GUI `ytec-winpe-gui.exe`
- LINE Seed JP Regular/BoldをEXE資源へ埋め込み、プロセス内限定で登録し、
  失敗時は`Yu Gothic UI`へフォールバック
- Tsumugiを表す3本の糸、青緑/紫の状態色、暗色サイドバー
- 1280x720基準、最小1040x650、標準コントロールによるTab操作
- 予約ジョブ、起動修復のみ、ディスク診断の3画面
- 全ディスクのバックグラウンド読取り専用列挙
- モデル、容量、GPT/MBR、BusType、セクター、シリアル末尾、
  パーティション一覧の表示
- 未解決の列挙診断、空一覧、不明な安全属性を実行候補にしない画面モデル
- `.json`ジョブの改ざん検査、復元`.dcimg`完全検証、
  安定識別による対象再解決
- C:～Z:（X:を除く）の固定/リムーバブル媒体で、ドライブ直下または
  `Tsumugi`直下の製品既定名だけを最大92候補として探す自動検出。
  一意な正規ジョブだけを自動プリフライトする。通常/v2ジョブは手動確認を
  維持し、Windows側で明示したv3 `auto-once`だけはSHA-256連動開始記録の
  新規保存・読戻し後に一度だけ自動開始する
- 既存/保存不能/不完全な開始記録では自動実行を止め、記録を削除せず
  同じジョブの二重自動実行を防ぐ。手動確認は残す
- 確認済みジョブのpayload SHA-256を実行時ローダーへ固定し、確認後の
  正規ジョブ差替えも物理I/O前に拒否
- 復元イメージのドライブ文字変更時に、同じ相対パスだけを有界探索
- UEFI/BIOS、対象ディスク、割当済みWindows/システム領域または
  一意な未割当ESP/Active領域の自動一時割当を選択
- 起動修復の読取り専用プリフライト、変更承認、対象固有語の完全一致
- Microsoft署名済みREAgentCの`/info`だけを使うWinRE読取り専用診断。
  登録済み回復領域、Windows内の補完候補、根拠不足による停止を分けて表示
- 起動修復実行直前の再列挙と、署名検証済みBCDBoot、BCD再読込み
- System32絶対パスの`comdlg32.dll`がないWinPEでは直接入力へフォールバック
- GPT/MBRクローンと合成dcimg復元から、現在工程、パーティション番号、
  読取り/書込み/読戻し検証済みバイト、合計、キャンセル可否を通知する
  共通進捗コールバック
- 経過時間と検証済みバイトから速度、進捗率、残り時間を算出する
  WinPE表示モデル。16 MiBかつ3秒未満では不安定な残り時間を表示しない
- WinPEApp実行境界から注入サービス、VM専用GPT/MBR実行サービス、
  クローンエンジンまで同じ進捗/キャンセルコールバックを中継
- クローン/復元ジョブの必須検査合格後だけ表示される対象消去承認、
  対象固有確認語、種別に応じた開始ボタン、安全キャンセル
- 製品クローン/復元サービスへの進捗中継と、工程、進捗率、検証済み容量、速度、
  経過時間、残り時間、中断可否の実GUI表示
- 工程または中断可否の変化時を除き100ms以下で更新しない進捗通知、
  実行中の多重開始/画面終了拒否
- 失敗/中止時に部分コピー先/復元先がofflineのまま保護される可能性を明示する結果表示
- 実行試行後にジョブハッシュ、種別、PASS/FAIL、完了UTC、製品版、
  詳細長/詳細SHA-256を64 KiB以下の時刻付き`.log`へ新規保存し、flushと
  全バイト読戻し後だけ保存済みと表示する結果保存

## 安全境界

- GUIのディスク診断とジョブ確認はターゲットを開きません。
- 直接`--clone-execute`へ製品サービスは注入せず、VM専用入口のまま分離します。
- 製品クローンは検証済み予約ジョブからだけ接続し、同じ呼出しでコピー元/
  コピー先の安定識別、空RAW、固定ディスク、既知BusType、対応GPT/MBR、
  容量/セクター、二段階確認を再検証します。コピー元の同一読取り専用
  ハンドルを保持した後だけコピー先をoffline化し、失敗/中止時はonlineへ
  戻しません。成功時は全書込み読戻しとパーティション表確定後だけ戻します。
- 復元は製品実行サービスへ接続し、同じ呼出しで全安全条件と二段階確認を
  再検証します。コピー元物理ディスクは開かず、同じ読取り専用dcimg
  ハンドルの完全検証とジョブ指紋一致後だけ復元先をoffline化します。
- 起動修復だけは利用者が明示的に依頼済みの製品機能として接続します。
- WinRE診断はBCD、回復設定、ディスクを変更せず、診断結果だけで
  MBR→GPT実行を有効にしません。
- 起動修復は固定ディスク、対応GPT/MBR、同一ディスク上のWindows/
  システム領域、AMD64ローダー、二段階確認、実行直前再識別を必須にします。
- ドライブ文字未割当領域は、対象固定ディスク上で一意なFAT32 ESPまたは
  Active `0x07` NTFSをVolume GUID、offset、extentまで再照合できる場合だけ、
  実行時に一時割当します。候補重複や既存マウントは推測せず停止します。
- 一時ドライブ文字はY:から降順にX:と全既知使用文字を除外し、BCDBoot後の
  明示解除成功まで完了扱いにしません。解除失敗も成功扱いしません。
- 非同期処理は画面で選んだディスク番号を信頼せず、サービス側で再列挙します。
- ディスク再読込みまたはジョブパス変更時は、以前の安全確認結果を無効化します。
- 自動検出は再帰探索せず、固定名候補の重複、複数の有効ジョブ、改ざん、
  reparse point、候補過多のいずれでも自動選択しません。
- 起動修復の完了後は確認語と対象選択を破棄し、同じ確認状態で再実行できません。
- キャンセルはデータコピーとパーティション表の仮配置中だけ受け付けます。
  最終確定開始後は中断不可として通知し、コールバックを再照会しません。
- データコピー中の中止では既に書いた内容をflushし、GPT/MBRの先頭側
  パーティション表を未確定のまま残します。
- 進捗通知コールバックの例外は破壊的エンジンへ伝播させず、
  キャンセル確認コールバックの例外は安全側に中止として扱います。

実WIM/ISO生成とVM内確認は管理者権限を要するため、利用者との
UAC一括作業で実施します。実機試験は最終段階まで行いません。

2026-08-01午前には、LINE Seed JP埋込み直前の完成ISO/manifestを発行し、
HDD/NICなしVMのLegacy BIOS、UEFI、Secure Boot有効/無効6条件で
日本語製品GUIの自動起動を確認しました。この証跡は媒体基盤の回帰として保持し、
現在差分の合格には数えません。

製品クローン/WinPE復元の転送単位は、既存エンジンの検証上限16 MiBへ
統一しました。64 GiBの論理コピーは旧4 MiB方針比でチャンクと同期I/O要求を
75%削減する決定論的試算を確認し、キャンセル確認間隔は最大16 MiBのままです。
3 MiBの同一合成復元では、1 MiB単位と比べて書込み/読戻し要求が3回から1回に
なり、出力全バイト、必須読戻し、最終パーティション表確定は同一でした。
