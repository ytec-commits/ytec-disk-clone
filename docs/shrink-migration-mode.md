# 縮小移行モード

更新日: 2026-08-03

## 目的

`縮小移行モード`は、コピー元の総容量より小さい空ディスクへ、実際に使用中の
NTFS内容と安全余白が収まる場合に限って移行するモードです。コピー元の
パーティションをその場で縮小せず、コピー元は読み取り専用のまま、コピー先だけに
新しいパーティションとファイルシステムを作ります。

## 対応範囲

| 操作 | 通常モード | 縮小移行モード |
|---|---|---|
| ドライブをクローン | 同容量以上へ構造を維持して複製 | 第三ディスクへ検証済み作業イメージを作り、小容量先へ再構成 |
| イメージを作成 | 単一ファイル`.dcimg` | ディレクトリ形式`.dcmig` |
| イメージを復元 | `.dcimg`を同容量以上の空ディスクへ復元 | `.dcmig`を計算済み最小容量以上の空ディスクへ再構成 |
| Windows起動ディスク | GPT/UEFIまたはMBR/Legacy BIOS | 同じGPT/MBR形式を維持し、展開後にコピー先だけへBCDを新規構築 |
| データ専用ディスク | GPT/MBR基本ディスク | GPT/MBR基本ディスク。起動構成は作成しない |

縮小移行ではMBRとGPTの形式を維持します。MBRからGPTへの変換は通常モードの
専用経路で扱い、縮小移行とは同時に行いません。

## `.dcmig`形式

`.dcmig`は1個のファイルではなく、末尾が`.dcmig`の新規ディレクトリです。
内部には正規バイナリ形式の`manifest.dcmig`と、各NTFS内容を格納した
Microsoft WIMファイルが入ります。マニフェストは次の情報を結び付けます。

- コピー元の安定ディスク識別、GPT/MBR、論理/物理セクター情報
- Windowsディスクかデータ専用ディスクか、および対応パーティションの役割
- 使用量、クラスター寸法、ラベル、WIMファイル名
- 各WIMの正確な長さとSHA-256
- MBR復元に必要な先頭440バイトのブートストラップ（GPTではゼロ固定）

作成時は一時ディレクトリへ保存し、全WIMとマニフェストの読戻し検証、VSSの
`BackupComplete`、Snapshot setの削除がすべて成功した後だけ最終名へ確定します。
既存ファイルや既存ディレクトリは上書きしません。復元時はディレクトリと
マニフェストを置換できない状態で読み取り専用ロックし、宣言外の項目、reparse、
長さ違い、SHA-256不一致を最初のコピー先書込み前に拒否します。

## 容量計算

内容を持つ各NTFS領域に、使用量と安全余白を加えて1 MiB境界で配置します。

- Windows領域: `使用量 + max(使用量の12.5%, 10 GiB)`
- データ領域: `使用量 + max(使用量の12.5%, 1 GiB)`
- 回復領域: 上記に加えて最低990 MiB
- GPT起動ディスク: ESP 200 MiB（4Knは300 MiB）とMSR 16 MiBを新規作成
- 残り容量: Windows領域を優先し、データ専用では最も使用量の多いデータ領域へ配分

コピー先が計算済み最小容量より小さい場合は、コピー先を変更する前に停止します。

## 安全境界と非対応

- コピー元は`GENERIC_READ`だけで開き、パーティション変更、縮小、ドライブ文字変更、
  VSS以外の状態変更を行わない
- コピー先は安定識別を再照合した、空のRAWまたは既知の基本GPT/MBR・非システム固定ディスクだけを許可する
- 確認後のWinPE実行境界でコピー先の先頭・末尾1 MiBを読戻し検証付きで無効化し、既存のNTFS等を置換する
- WinPEでDISMが使う一時作業フォルダーは、実行中WinPEのシステムドライブ上に
  固定し、親参照、欠落フォルダー、reparse pointを拒否する
- GPT/MBRの基本ディスクと基本NTFS内容だけを対象にする
- BitLockerは完全復号を確認できない場合に停止する。回復キー回避は行わない
- 起動可能な縮小移行はAMD64版Windowsを対象とし、Windows 7は未保証とする
- 動的ディスク、Storage Spaces、不明な区画種別、FAT/exFATデータ領域、
  あいまいなWindows構成、4Knへの製品書込みは現時点で対象外
- 直接クローンでは、コピー元・コピー先とは別の物理ディスク上に、未使用名の
  `.dcmig`作業領域が必要。作業領域を介して原本とコピー先を同時変更しない
- オンラインイメージ作成でも、保存先と一時作業フォルダーは原本とは別の同じ
  単一物理ディスクに限定し、開始時、Snapshot取得後の保存直前、完成名確定前に再確認する
- データ専用ディスクではBCDBoot、ESP、Active起動領域を作成しない

新しい第三者依存は追加していません。ファイル単位の取得・展開とNTFS初期化には、
現在のWindows/WinPEに含まれるMicrosoft DISM、FORMAT、BCDBootだけを、固定パス、
固定引数、Microsoft署名再検証の境界から使用します。

## 検証状態

- レイアウト、ジョブv4、`.dcmig`正規形式、読取り専用ロック、WIM作成/適用、
  GPT/MBRメタデータ、通常/縮小の選択、データ専用復元の単体・合成試験は合格
- 製品VMハーネスで、4 GiBの合成データ専用原本から2 GiBのRAWコピー先へ
  オンラインVSSバックアップと縮小復元を完走
- 原本不変、復元ファイル一致、Snapshot残留0件、データ専用時のBCDBootなし、
  自動マウント/Shell状態復元を確認
- FORMATには、Volume GUIDとNTデバイスの一時照合後にMount Managerへ登録し、
  再照合したドライブ文字だけを渡す。解除も所有したマウントポイントだけに限定
- 固定VMが`stopping`へ固着した場合も、VM名、UUID、実行ファイル、全
  `VirtualBoxVM.exe`プロセスが一致した場合だけ回復し、SATA 4/5を切り離す
- 証跡: `.validation/evidence/product-data-shrink-vm/20260803-224747/`
- 最終全CI: 通常/静的CRT/ASan各43/43、MSVC静的解析、全境界検査PASS

これらは合成ディスクでの実機前検証です。一般利用可能または実機互換を保証する
ものではなく、代表実機での受入は別途必要です。
