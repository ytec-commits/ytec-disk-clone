## 横断要件

### Windows版GUI

ネイティブWin32の製品画面を追加し、読み取り専用ディスク列挙、
安全な既定選択、コピー先の画面側フェイルクローズ、機能ナビゲーション、
進捗/残り時間の表示モデルを実装しました。クローンはコピー先情報の確認1/2、
対象固有語の完全一致を要求する確認2/2を通り、ハッシュ付きジョブだけを
既存ファイル非上書きで保存できます。クローン/イメージ作成/復元画面には
`通常モード（完全複製）`と`縮小移行モード（小容量へ）`を追加し、Windows
起動ディスクとデータ専用GPT/MBR基本ディスクの両方を選べます。標準権限では
ボタンを無効化して自動UACを行いません。管理者実行時はコピー元を読取り専用で
再識別し、VSS完了とSnapshot削除後だけ新規`.dcimg`ファイルまたは`.dcmig`
ディレクトリへ確定する製品サービスへ接続済みです。
この製品経路は固定VMで容量不足、コピー中止、正常完了を実行し、
全経路のSnapshot残留0件と正常経路の完成`.dcimg`確定を確認済みです。
アプリ起動ごとに実行ファイル横の`logs`へ既存非上書きのUTF-8 BOMログを
作成します。レベル、時刻、製品版、OS版、権限、マスク済みディスク要約、
VSS/媒体/復元の段階、ネイティブエラーコードを記録し、ログSinkの例外や
書込み失敗を製品操作へ伝播しません。ファイル名一覧、ユーザープロファイル
絶対パス、デバイスパス、完全シリアル、文書内容、製品/BitLockerキーは
ログ本文へ記録しません。「ログ・診断」画面は権限、検出台数、注意件数、
最大5台の概要とログ名を表示し、更新操作も読取り専用です。
同じ更新で固定/リムーバブル媒体の固定位置だけからWinPE結果ログを最大256件
列挙し、正規UTF-8、詳細長/SHA-256、完全再生成、ファイル名との種別/UTC一致を
検証して最新結果を表示します。不正候補が1件でもあれば部分結果を表示しません。
レスキューメディア画面は標準権限でADK/WinPE Add-on、Microsoft署名、
検証済みバージョン、必須更新、`/bootex`を読み取り専用診断し、
作成許可ゲートを表示します。合格後は「環境確認→形式・出力先→内容確認→作成」
の4段階でISO/USBと2011/2023 CAを選択できます。ISOはローカル絶対`.iso`
新規パスだけ、USBは非システム、USB接続、取り外し可能、オンライン、
非読み取り専用、既知パーティション形式、安定識別をすべて満たす候補だけを
作成内容確認へ進めます。標準権限では出力を開かず安全に停止し、自動UACを
要求しません。管理者として手動起動した配布版では、同梱した自作
MediaBuilder/診断CLI/WinPE CLI/GUIとSystem32の署名済みWindows PowerShellを
固定位置から再検証し、選択した完成ISOと新規一時作業先を分離して
製品ISOサービスへ渡します。作業領域、WIMマウント、日本語化、製品照合、
ISO生成、完成名確定、全量SHA-256を逐次表示し、経過時間から目安残り時間を
更新します。USBは実行直前に物理ディスクを読み取り専用で再列挙し、
安定識別の一意一致、ディスク番号不変、非システム/USB/取り外し可能/
online/非read-only、列挙問題なし、二段階確認語一致までを再判定する純粋な
事前認可を実装しました。認可結果も`physical_write_started=false`を固定し、
その後に同じ対象だけを再識別して、ローカルADKの公式
`MakeWinPEMedia /UFD /F`を1回だけ呼ぶ製品実作成サービスへ接続しました。
完了後も同じUSBを再識別し、作業媒体との全ファイル長/SHA-256一致を
完了条件にします。物理USBへの実測前なので利用可能とは扱いません。
さらにローカル固定/リムーバブルドライブを
Desired Access 0で開き、単一`IOCTL_VOLUME_GET_VOLUME_DISK_EXTENTS`、
選択した物理ディスク番号、パーティション開始位置/容量、ドライブ文字を
一意照合します。複数ディスク、複数文字、容量外、区画不一致は停止し、
この照合もロック、アンマウント、フォーマット、書込みを行いません。
イメージ復元画面はローカル通常ファイル`.dcimg`または`.dcmig`内の固定名
`manifest.dcmig`を読取り専用で開き、通常形式の全チャンク、縮小形式の全WIM、
マニフェスト、パーティション構成、長さ/SHA-256を完全検証します。合格後も
`restore_execution_enabled=false`を固定します。列挙済み情報だけを使う
復元先候補欄では、安定識別、元ディスクとの同一性、現在のWindowsディスク、
読取り専用/リムーバブル/不明状態、パーティション形式、容量、論理セクターを
確認します。候補合格は後続確認へ進めることだけを示し、復元先ディスクは
開きません。対象情報の確認1/2と対象固有語の完全一致2/2の後は、
ハッシュ付き復元予約ジョブだけを新規保存し、全バイトとSHA-256を
読戻し検証します。Windows側では実行前詳細検査と物理復元はまだ行いません。

### WinPE版GUI

ネイティブWin32の`ytec-winpe-gui.exe`を追加しました。初期画面から
「予約ジョブ」「起動修復のみ」「ディスク診断」へ移動でき、Tsumugiの
3本の糸を表すヘッダー、4段階ステップ、状態色、操作結果を日本語で表示します。
予約ジョブ画面は既存のハッシュ/イメージ完全検証/ディスク再識別境界を
バックグラウンドで呼び、クローン/復元の厳格な実行前条件を満たす場合だけ
対象別の二段階確認から製品予約ジョブ実行サービスへ進みます。
起動時は固定/リムーバブル媒体の固定名/固定位置だけを有界検索し、一意な
正規ジョブだけを自動プリフライトします。複数、重複、改ざん候補は停止し、
実行時も承認済みジョブSHA-256へ固定します。実行試行後の結果ログは
時刻付き新規名でジョブ横へ保存し、flush/全バイト読戻し後だけ保存済みとします。
起動修復画面は固定ディスク、Windows領域、割当済みシステム領域または
一意に識別できる未割当ESP/Active領域、UEFI/BIOSを選択し、読み取り専用検査、
変更承認、対象固有語の完全一致後だけ、既存の実行直前再識別付きBCDBoot
サービスへ渡します。自動モードは実行時だけ一時ドライブ文字を割り当て、
明示解除成功まで完了扱いにしません。ディスク診断は
シリアル末尾だけを表示し、不明属性を安全候補にしません。
クローン/復元エンジンの共通進捗を、現在工程、パーティション、読取り/
書込み/検証済み容量、速度、経過時間、残り時間、中断可否へ変換する
表示モデルを追加しました。製品クローン/復元サービスから同じ
コールバックを中継し、GUIの中断要求も安全な境界へ渡します。
製品経路の完走/中止/破損拒否は専用VMで確認済みですが、コピー先単独起動と
実機試験前であり、利用可能/リリース可能とは扱いません。

製品媒体生成で静的CLI/GUIを両方ハッシュ検査してWIMへ追加し、
GUIを自動起動しました。日本語表示には利用者のローカルADKにある
`WinPE-FontSupport-JA-JP.cab`だけをDISMで追加し、CAB/WIM/ISOを
リポジトリへコピーしません。Windows PowerShell 5.1のmanifest保存不具合を
修正後、LINE Seed追加直前版の2011/2023 CA完成ISO/manifest発行と
Legacy BIOS/UEFI/Secure Boot 6条件を完了しました。現在はLINE Seed/OFL入り
ISOの再生成と、ドライブ文字未割当ESP/Active領域の一時割当・必須解除を含む
現在差分の実WinPE VM確認を残しています。

### ジョブ引き継ぎ

クローン、イメージ作成、復元、MBR→GPT用の正規UTF-8 JSON v4を実装しました。
v2/v3は正規旧形式として読込み、`transferMode`は安全側に`exact`へ固定します。
payloadのWindows CNG SHA-256、64 KiB上限、厳格な項目順/文字表現、
未知項目/不正UTF-8/末尾データ拒否を含みます。WinPEAppの
`--job-preflight`は通常ファイルを読み取り専用で開き、ハッシュ検証後に
安定識別情報でディスク番号を再解決します。復元ジョブではディスク列挙前に
共通ImageFormat/MigrationEngine検証器で`.dcimg`全体と全チャンク、または
`.dcmig`マニフェストと全WIMを再検証し、復元先容量、論理セクター、
元ディスクとの分離も確認します。
ドライブ文字が変わった場合は`--image-path`で再選択でき、ジョブに記録した
ファイル長とdcimg全体SHA-256の両方が一致しない限りディスク列挙へ進みません。
`--search-image`では固定/リムーバブル媒体の同じ相対パスだけを最大23候補として
有界列挙し、各候補の完全検証と指紋一致後だけ自動再解決します。
WinPEでは検証済みマニフェストからBitLocker完全復号と対応ファイルシステム、
再列挙結果から既知LDM型とStorage Spaces、Windows APIからAC電源を
読取り専用で三値判定します。不明な必須項目は不合格とし、再起動保留は
仕様どおり警告`unknown`として残します。`--job-preflight`単体は
必須検査がすべて合格しても`executionEnabled=false`を固定し、
別の`--job-execute`だけが再検証と二段階確認後に製品実行サービスへ進みます。
任意フォルダの再帰探索は安全性と待ち時間を限定できないため行いません。

### 起動修復のみ

通常製品WinPEAppへ、クローンと独立したUEFI/BIOS起動修復を接続済みです。
UEFI64/Secure Boot有効VMでは、BCD破損、`0xc0000098`起動失敗、
製品CLI修復、Microsoft署名確認、BCD再読込み、Windows再起動まで完了しました。
Legacy BIOS x64 VMでもBCD破損後の`0xc000000e`、製品CLI修復、
Windowsデスクトップへの単独起動まで完了しました。

### 縮小移行モードとデータ専用ディスク

コピー元総容量ではなく、基本NTFSの実使用量、安全余白、必須起動領域から
コピー先最小容量を決める`MigrationCore`と、読取り専用のコピー元解析、
VSS/DISM WIM取得、`.dcmig`束の非上書き確定・完全検証、コピー先GPT/MBRの
再作成、FORMAT、WIM適用、読戻し、WindowsディスクだけのBCDBootを行う
`MigrationEngine`を製品ジョブへ接続しました。直接クローンは、原本とコピー先の
どちらでもない第三物理ディスクへ作業`.dcmig`を確定してから復元します。

データ専用ディスクではWindows/ESP/Active役割を要求せず、基本NTFS内容だけを
移行し、BCDBootを呼びません。通常`.dcimg`と縮小`.dcmig`の作成・復元の両方で
この役割をマニフェストへ固定します。動的ディスク、Storage Spaces、BitLocker
未復号、未知のGPT/MBR種別、非NTFS内容は最初のコピー先書込み前に拒否します。

レイアウト、マニフェスト、ジョブv4、GUI選択、復元プリフライト、WIM束、
GPT/MBRメタデータ、データ専用時の起動処理抑止は単体・合成試験済みです。
4 GiBの合成データ専用原本から2 GiB RAWへVSS作成・縮小復元する製品VM試験は
PASSしました。原本不変、復元ファイル一致、Snapshot残留0件、データ専用時の
BCDBoot抑止、自動マウント/Shell状態復元を確認しています。詳細は
[縮小移行モード](shrink-migration-mode.md)を参照してください。

### 性能

コピー/復元は最大16 MiBの有界チャンクを使い、製品クローンとWinPE復元も
この既存検証上限へ統一し、全チャンクを書込み直後に読戻し検証します。
512バイト論理セクターだけを許す製品境界は変えず、4Knは引き続き拒否します。
今回、読取り/書込み/検証済み容量を別々に
単調通知し、検証済み容量を基準に速度と残り時間を計算できるようにしました。
64 GiBの論理コピーでは旧4 MiB方針の16,384チャンクに対して4,096チャンクと
なり、読取り/書込み/必須読戻しの要求回数を各75%削減する決定論的試算を
モック検証しました。3 MiBの同一合成復元では、1 MiB単位と比べて16 MiB単位で
書込み/読戻し呼出しが
3回から1回になり、出力全バイトと最終パーティション表確定は同一でした。
キャンセル確認間隔は最大16 MiBの論理転送に限定し、不安定な初期推定は
表示しません。バッファ再利用、非同期パイプライン、実VMでの実スループットと
秒単位のキャンセル応答は未確定です。安全性と形式互換性を
変えない範囲だけ、同じ合成データとVMで変更前後を比較します。

静的ランタイム版CLI/GUIを自作ファイルだけの読み取り専用VISOへ載せ、
既存の検証済み2023 CA WinPEから起動しました。EFI64、Secure Boot有効、
